# ทดลองข้อมูลทยอยเข้า 5/10/15 วินาที

ต้นแบบ Python นี้อ่านคลิปทีละเฟรม เก็บ RGB ก่อน interpolation และคำนวณใหม่จากข้อมูลล่าสุดเท่านั้น
ยังไม่ใช่เว็บไซต์หรือกล้องสด และไม่ได้รอให้คลิปเล่นตามนาฬิกาจริง

## วิธีรันในเครื่อง

จากโฟลเดอร์ SCiUS-Project:

```powershell
& "..\.venv\Scripts\python.exe" "ippg\replay_realtime.py"
```

ค่าเริ่มต้นใช้ vid.avi และ ground_truth.txt ของ subject1 ที่เคยทดลอง หากเปลี่ยนคู่ข้อมูล:

```powershell
& "..\.venv\Scripts\python.exe" "ippg\replay_realtime.py" "C:\data\subject2\vid.avi" --reference "C:\data\subject2\ground_truth.txt"
```

reference ต้องมี 3 แถว: PPG, BPM ที่ให้มา และเวลาเป็นวินาที ถ้าไม่ระบุ --reference จะหา ground_truth.txt ข้างวิดีโอ
ต้องตรวจว่าคู่ข้อมูลตรงกันจริงก่อนรัน

## วิธีทำงาน

1. ใช้ฟังก์ชันตรวจหน้า เรียนรู้สีผิว และดึง RGB แบบ legacy ตามโค้ดเดิม บันทึกทุกเฟรมรวมช่วงใช้ไม่ได้
2. เก็บเฉพาะข้อมูลย้อนหลังสูงสุด 15 วินาทีใน buffer สำหรับคำนวณ
3. อัปเดตทุก 1 วินาที เริ่มนับจากเวลาเฟรมแรก คำนวณรอบที่กำหนดก่อนรับเฟรมที่เกิดหลังรอบนั้น
4. เลือกข้อมูล 5/10/15 วินาที จัดเวลาใหม่เฉพาะช่วง แล้วทำ POS → DWT → Band-pass → FFT ใหม่ ไม่ใช้สัญญาณที่กรองทั้งคลิป
5. ข้อมูลยังไม่ครบให้ collecting; ขาดช่วงเกิน 0.25 วินาทีหรือสัญญาณใช้ไม่ได้ให้ unavailable เกณฑ์นี้เป็นจุดเริ่มทดลอง ยังไม่ใช่ quality gate ที่ยืนยันแล้ว
6. reference ใช้เฉพาะ timestamp ที่มาถึงแล้ว รวมเวลาซ้ำด้วยค่าเฉลี่ยและกรอง order-3 SOS บน grid เดียวกับ iPPG ที่ sampling rate ของวิดีโอ ไม่มีการเลื่อน/ยืดเวลา

ถ้า reference ที่มาถึงแล้วไม่ครอบคลุม grid จะไม่ extrapolate และไม่คิดส่วนต่างในรอบนั้น แม้ iPPG ยังมีผลได้
ส่วน iPPG ไม่ใช้ reference เลือกหน้าต่างหรือประมาณ BPM

ตัวกรองยังเป็นแบบไป–กลับบนหน้าต่างล่าสุดที่มีครบ ไม่ใช่ตัวกรอง causal แบบอัปเดตทีละ sample
วิธีนี้ให้ผลประมาณย้อนหลังทั้งหน้าต่างได้ แต่ยังต้องตรวจความผิดพลาดขอบหน้าต่างและความหน่วงจริง

## ไฟล์ผลลัพธ์

แต่ละรอบสร้างโฟลเดอร์ใหม่ใต้ outputs/realtime_replay:

| ไฟล์ | เนื้อหา |
|---|---|
| observations.csv | เวลา RGB สถานะ และเวลาสกัดข้อมูลทุกเฟรม ก่อนจัดเวลาใหม่ |
| updates.csv | ผลทุกหน้าต่างทุกรอบ รวม collecting และ unavailable |
| summary.csv | จำนวนรอบ เวลาแรก MAE ทุกคู่/เวลาร่วม ความผิดพลาดสูงสุด และเวลาคำนวณ |
| window_stages.npz | grid, RGB, POS, หลัง DWT, หลังกรอง, FFT และ reference; key rowNNNN ตรงกับลำดับแถวข้อมูลใน updates.csv เริ่มที่ 0 |
| comparison.png | กราฟ BPM ส่วนต่าง และเวลาคำนวณ |
| manifest.json | สถานะ config, clock, source/model/code hashes และ hashes ไฟล์ผลลัพธ์ |
| RESULT.md | ผลและข้อจำกัด |

buffer คำนวณจำกัดเวลา แต่ข้อมูลบันทึกและ stages สะสมทั้งคลิป ก่อนใช้กล้องไม่จำกัดเวลาต้องออกแบบการส่งออก log แยก
